# 数据质量规则类型详解

本文档详细说明系统中支持的所有数据质量规则类型，包括每种类型的用途、配置格式和典型应用场景。

## NOT_NULL（非空校验）

**用途**：检测字段值是否为 NULL 或空字符串，确保关键业务字段必须有值。

**适用场景**：
- 用户表的姓名、手机号等必填字段
- 订单表的订单号、金额等核心字段
- 任何业务上不允许为空的字段

**ruleConfig 格式**：
```json
{}
```

**示例**：
```json
{
    "ruleName": "用户姓名非空校验",
    "ruleType": "NOT_NULL",
    "column": "name",
    "ruleConfig": {},
    "description": "用户表的姓名字段不允许为空"
}
```

**注意事项**：
- 空字符串（""）和纯空格字符串也被视为空值
- 数值 0 不算空值
- 对于有 DEFAULT 值的字段，需确认是否仍需非空校验

---

## UNIQUE（唯一性校验）

**用途**：检测字段中是否存在重复值，确保字段值的唯一性。

**适用场景**：
- 用户表的用户名、邮箱、手机号（不可重复）
- 订单表的订单编号（全局唯一）
- 商品表的商品编码（SKU 唯一）
- 任何业务上要求唯一标识的字段

**ruleConfig 格式**：
```json
{}
```

**示例**：
```json
{
    "ruleName": "用户手机号唯一性校验",
    "ruleType": "UNIQUE",
    "column": "phone",
    "ruleConfig": {},
    "description": "用户表的手机号不允许重复"
}
```

**注意事项**：
- NULL 值不参与唯一性比较（多个 NULL 不算重复）
- 大小写敏感性取决于数据库 collation 设置
- 对于大表，唯一性校验可能耗时较长

---

## LENGTH（长度校验）

**用途**：校验字符串字段的字符数是否在指定范围内。

**适用场景**：
- 用户名称 2~20 个字符
- 密码长度 6~32 位
- 地址信息不超过 200 字符
- 备注字段不超过 500 字符

**ruleConfig 格式**：
```json
{
    "minLength": 最小长度（整数，可选）,
    "maxLength": 最大长度（整数，可选）
}
```

**示例**：
```json
{
    "ruleName": "用户名称长度校验",
    "ruleType": "LENGTH",
    "column": "name",
    "ruleConfig": {"minLength": 2, "maxLength": 20},
    "description": "用户名称长度须在2到20个字符之间"
}
```

**注意事项**：
- 长度按字符数计算，中文算1个字符
- minLength 和 maxLength 可以只填一个，表示单边限制
- 该规则仅适用于字符串类型字段（VARCHAR、CHAR、TEXT 等）

---

## RANGE（范围校验）

**用途**：校验数值型字段的值是否在指定的最小值和最大值之间。

**适用场景**：
- 年龄字段 0~150
- 商品价格 > 0
- 评分字段 1~5
- 百分比字段 0~100
- 库存数量 >= 0

**ruleConfig 格式**：
```json
{
    "min": 最小值（数值，可选）,
    "max": 最大值（数值，可选）
}
```

**示例**：
```json
{
    "ruleName": "用户年龄范围校验",
    "ruleType": "RANGE",
    "column": "age",
    "ruleConfig": {"min": 0, "max": 150},
    "description": "用户年龄须在0到150之间"
}
```

**注意事项**：
- 该规则仅适用于数值型字段（INT、BIGINT、DECIMAL、FLOAT 等）
- min 和 max 可以只填一个，表示单边限制
- 边界值包含在内（即 >= min 且 <= max）

---

## REGEX（正则校验）

**用途**：使用正则表达式校验字段值的格式，适用于有固定格式要求的字段。

**适用场景**：
- 手机号格式（如中国大陆手机号）
- 邮箱格式
- 身份证号格式
- URL/域名格式
- 邮政编码
- 车牌号、银行卡号等固定格式

**ruleConfig 格式**：
```json
{
    "pattern": "正则表达式"
}
```

**示例**：
```json
{
    "ruleName": "手机号格式校验",
    "ruleType": "REGEX",
    "column": "phone",
    "ruleConfig": {"pattern": "^1[3-9]\\d{9}$"},
    "description": "手机号须符合中国大陆11位手机号格式"
}
```

**注意事项**：
- 正则表达式使用 MySQL REGEXP 语法
- 建议使用 `^` 和 `$` 锚定首尾，避免部分匹配
- 转义字符使用双反斜杠（\\d 而非 \d）
- 详见「正则表达式常用模式库」知识文件获取更多模式

---

## ENUM（枚举校验）

**用途**：校验字段值是否在指定的枚举列表中。

**适用场景**：
- 性别字段（男/女/未知）
- 状态字段（启用/禁用、待审核/已通过/已拒绝）
- 类型字段（如订单类型：普通/预售/秒杀）
- 支付方式（微信/支付宝/银行卡/现金）

**ruleConfig 格式**：
```json
{
    "values": ["值1", "值2", "值3"]
}
```

**示例**：
```json
{
    "ruleName": "用户性别枚举校验",
    "ruleType": "ENUM",
    "column": "gender",
    "ruleConfig": {"values": ["男", "女", "未知"]},
    "description": "性别字段只能为男、女或未知"
}
```

**注意事项**：
- 枚举值使用字符串格式，即使原值是数字也要写成 "0"、"1"
- 枚举值区分大小写
- 枚举列表不宜过长（建议不超过 20 个值），否则考虑用字典表

---

## CUSTOM_SQL（自定义SQL校验）

**用途**：通过自定义 SQL 查询来检测数据质量问题，适用于复杂业务逻辑。

**适用场景**：
- 跨表一致性校验（如订单表金额与明细表汇总是否一致）
- 复杂的业务规则（如开始日期必须早于结束日期）
- 关联数据完整性（如订单的客户ID必须存在于客户表）
- 任何无法用简单规则表达的复杂校验

**ruleConfig 格式**：
```json
{
    "sql": "自定义SQL查询语句"
}
```

**示例**：
```json
{
    "ruleName": "订单金额一致性校验",
    "ruleType": "CUSTOM_SQL",
    "column": "total_amount",
    "ruleConfig": {"sql": "SELECT o.id FROM tb_order o WHERE o.total_amount != (SELECT SUM(oi.amount) FROM tb_order_item oi WHERE oi.order_id = o.id)"},
    "description": "订单总金额须等于订单明细金额之和"
}
```

**注意事项**：
- SQL 查询返回的结果行代表"异常数据"，返回空结果集表示校验通过
- SQL 中可以直接引用表名和字段名
- 注意 SQL 性能，大表建议加 WHERE 条件限制范围
- 该规则类型需要用户具备一定 SQL 能力
