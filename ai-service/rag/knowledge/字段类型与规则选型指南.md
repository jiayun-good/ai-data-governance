# 字段类型与规则选型指南

本文档根据数据库字段的数据类型，指导如何选择最合适的数据质量规则类型。

---

## 一、字段类型 → 推荐规则对照表

| 字段类型 | 适用规则 | 不适用规则 | 说明 |
|---------|---------|-----------|------|
| VARCHAR / CHAR | NOT_NULL, UNIQUE, LENGTH, REGEX, ENUM | RANGE | 字符串类型优先用 LENGTH 而非 RANGE |
| TEXT / LONGTEXT | NOT_NULL, LENGTH | UNIQUE, RANGE | TEXT 不建议做唯一性（性能差） |
| INT / BIGINT | NOT_NULL, UNIQUE, RANGE | LENGTH | 数值类型用 RANGE 而非 LENGTH |
| DECIMAL / FLOAT / DOUBLE | NOT_NULL, RANGE | LENGTH, UNIQUE | 浮点数通常不做唯一性 |
| DATE / DATETIME / TIMESTAMP | NOT_NULL, RANGE | LENGTH, REGEX | 日期范围用 RANGE（比较时间戳） |
| BOOLEAN / TINYINT(1) | NOT_NULL, ENUM | RANGE, LENGTH | 布尔型用 ENUM 限定 0/1 |
| ENUM (MySQL) | NOT_NULL, ENUM | RANGE | 数据库已有枚举约束，可叠加应用层 ENUM |

## 二、按字段名语义推荐规则

### 2.1 名称类字段
- **常见字段名**：name, username, real_name, nickname, title
- **推荐规则组合**：
  1. NOT_NULL（名称不能为空）
  2. LENGTH（限制名称长度，如 minLength=1, maxLength=50）

### 2.2 账号/编码类字段
- **常见字段名**：username, login_name, account, code, no, number
- **推荐规则组合**：
  1. NOT_NULL（编码不能为空）
  2. UNIQUE（编码不能重复）
  3. REGEX（限定编码格式，如纯数字或字母+数字）

### 2.3 联系方式字段
- **常见字段名**：phone, mobile, email, tel
- **推荐规则组合**：
  1. NOT_NULL（联系方式不能为空）
  2. REGEX（手机号格式、邮箱格式）
  3. UNIQUE（手机号/邮箱不可重复，视业务而定）

### 2.4 金额/价格字段
- **常见字段名**：price, amount, total, cost, fee, salary
- **推荐规则组合**：
  1. NOT_NULL（金额不能为空）
  2. RANGE（min=0 或 min=0.01，金额不为负）

### 2.5 数量/库存字段
- **常见字段名**：quantity, stock, inventory, count, num
- **推荐规则组合**：
  1. RANGE（min=0，数量不为负）

### 2.6 状态/类型字段
- **常见字段名**：status, type, state, category, level, role
- **推荐规则组合**：
  1. NOT_NULL（状态不能为空）
  2. ENUM（限定合法状态值列表）

### 2.7 时间字段
- **常见字段名**：create_time, update_time, create_date, operate_time
- **推荐规则组合**：
  1. NOT_NULL（时间不能为空）

### 2.8 地址字段
- **常见字段名**：address, location, addr
- **推荐规则组合**：
  1. NOT_NULL（地址不能为空，视业务）
  2. LENGTH（限制地址长度，如 maxLength=200）

### 2.9 描述/备注字段
- **常见字段名**：description, remark, comment, note, memo
- **推荐规则组合**：
  1. LENGTH（限制长度，如 maxLength=500）

### 2.10 逻辑删除字段
- **常见字段名**：is_deleted, deleted, del_flag
- **推荐规则组合**：
  1. ENUM（values: ["0", "1"]）

## 三、选型决策流程

按照以下优先级顺序判断，**命中即停**：

```
1. 用户说"不能为空"/"必填"/"非空" → NOT_NULL
2. 用户说"不能重复"/"唯一"/"不可重复" → UNIQUE
3. 字段是字符串 且 涉及长度限制（"N个字以内"/"长度不超过"） → LENGTH
4. 字段是数值 且 涉及大小边界（"大于"/"小于"/"范围"） → RANGE
5. 涉及固定格式（手机号/邮箱/身份证等正则可表达的模式） → REGEX
6. 涉及有限枚举值（"只能是..."/"状态必须是..."） → ENUM
7. 以上都不满足，且规则逻辑复杂（跨表、多字段联合） → CUSTOM_SQL
```

## 四、常见错误选型及纠正

| 错误场景 | 错误选型 | 正确选型 | 原因 |
|---------|---------|---------|------|
| 年龄字段用 LENGTH | LENGTH | RANGE | 年龄是数值，应用范围校验而非长度校验 |
| 状态字段用 REGEX | REGEX | ENUM | 状态是有限枚举，用 ENUM 更直观 |
| 金额字段用 LENGTH | LENGTH | RANGE | 金额是数值，应用范围校验 |
| 手机号用 LENGTH | LENGTH | REGEX | 手机号有格式要求，REGEX 更精确 |
| 性别用 RANGE | RANGE | ENUM | 性别是有限枚举值，不是连续数值范围 |
| 跨表一致性用 NOT_NULL | NOT_NULL | CUSTOM_SQL | 跨表校验需要 SQL 查询 |

## 五、多规则组合建议

同一字段可以配置多条规则，常见组合：

### 5.1 手机号字段
1. NOT_NULL → 手机号不能为空
2. UNIQUE → 手机号不能重复
3. REGEX → 手机号格式校验

### 5.2 邮箱字段
1. NOT_NULL → 邮箱不能为空
2. UNIQUE → 邮箱不能重复
3. REGEX → 邮箱格式校验

### 5.3 用户名/登录名
1. NOT_NULL → 用户名不能为空
2. UNIQUE → 用户名不能重复
3. LENGTH → 用户名长度限制
4. REGEX → 用户名格式（只允许字母数字下划线）

### 5.4 订单金额
1. NOT_NULL → 金额不能为空
2. RANGE → 金额必须大于0
